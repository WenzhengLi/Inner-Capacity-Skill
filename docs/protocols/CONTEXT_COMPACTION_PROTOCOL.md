# 上下文压缩协议

用途：防止长期对话、跨多轮文件修改、故事训练、投资分析、Skill 校准和协议沉淀过程中，因上下文过长导致 Agent 忘记最新指令、误用旧 Skill、丢失文件改动因果链。

## 核心原则

Agent 不一定能直接控制软件级上下文压缩，也不一定总能读取精确的上下文使用百分比。

但 Agent 必须控制自己的行为级压缩：

- 在上下文接近上限前主动生成可恢复摘要。
- 在系统发生压缩、摘要、续接或上下文切换后，先回读关键状态文件，再继续执行。
- 不把压缩摘要当作唯一事实来源；涉及文件、状态、日志、健康、命理、财务、代码时，必须回读原文件或权威来源。

## 80% 强制规则

每次执行用户新指令前，先检查上下文预算。

如果软件层暴露上下文使用率：

- 使用率 `< 80%`：继续按 Router 执行。
- 使用率 `>= 80%`：先执行本协议的“行为级压缩”，再开始执行用户任务。

如果软件层不暴露精确使用率，则出现以下任一情况时，按“可能超过 80%”处理：

- 对话已经跨多轮复杂任务。
- 本轮或最近几轮读取了大量文件。
- 本轮或最近几轮修改了多个协议、Skill、模板或日志。
- 用户目标经历过中断、恢复、上下文压缩、自动续写或任务切换。
- Agent 发现自己需要依赖“刚才读过/刚才改过”的大量上下文才能继续。
- 任务涉及长期记忆、双 Skill 切换、校准分数、投资分析、故事作业评分、健康/命理记录或仓库结构修改。

## 行为级压缩内容

压缩摘要必须保留：

1. 用户最新指令和真实意图。
2. 当前阶段状态：
   - `stage`
   - `analysis_skill_path`
   - `analysis_calibration_score`
   - `conversation_skill_path`
   - `conversation_skill_version`
3. 当前任务类型和应读取的协议。
4. 最近已修改文件、修改目的和验证结果。
5. 当前任务的关键证据、判断、边界和未完成动作。
6. 不可丢失的用户偏好和禁止事项。
7. 下一步应该执行什么，以及不应该执行什么。

## 压缩后的恢复检查

发生压缩、摘要续接、长任务恢复或上下文切换后，继续工作前必须重新读取：

1. `user-space/SYNC_STATE.json`
2. `user-space/state.json`
3. `user-space/CONTEXT_SUMMARY.md`（如果存在）
4. `analysis_skill_path` 指向的分析 / 校准 Skill
5. `conversation_skill_path` 指向的对话 / 执行 Skill
6. `docs/protocols/AGENT_ROUTER_PROTOCOL.md`
7. 当前任务对应协议或 Skill
8. 涉及写入时，回读目标文件的当前内容

## 双 Skill 必保字段

压缩摘要和恢复检查中，必须保留并校验以下事实：

- 分析 Skill = 持续校准，不负责直接对话。
- 对话 Skill = 版本化执行，不随便覆盖。
- 校准分数 = 0-100；达到 100 后生成下一版对话 Skill。
- `user-space/` = 私人数据，不写入公开文档。
- 故事日志自动记录可以写入；其他 `user-space/` 写入按 Router 安全边界执行。

## 禁止事项

- 不得因为压缩摘要里写了某个结论，就跳过源文件检查。
- 不得在压缩后继续执行旧任务，而忽略用户最新消息。
- 不得把分析 Skill 当作对话 Skill。
- 不得把投资、健康、命理、法律、财务等高风险判断只建立在摘要上。
- 不得为了节省上下文而省略关键边界、文件路径和未完成动作。

## 推荐摘要模板

```text
上下文压缩摘要
- 最新用户指令：
- 当前任务类型：
- 当前状态：
  - stage:
  - analysis_skill_path:
  - analysis_calibration_score:
  - conversation_skill_path:
  - conversation_skill_version:
- 最近读取：
- 最近修改：
- 已验证：
- 关键判断：
- 用户偏好 / 禁止事项：
- 下一步：
- 不要做：
```
