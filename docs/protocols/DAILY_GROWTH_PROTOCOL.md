# 每日成长协议

状态：草案，供后续写入正式 `SKILL.md`。

## 触发词

当用户发送【开始】时，先判断是否已经完成迁移版初始化。若 `user-space/state.json` 不存在或 50 道题未完成，优先遵循 `docs/protocols/ONBOARDING_PROTOCOL.md`；若用户个人评估已完成，再进入每日成长检查模式。

注意：

- 【开始】不再触发讲故事。
- 【继续】不再作为故事触发词。
- 【讲故事】才进入寓言故事训练模式。

## 每日提问

用户发送【开始】后，Skill 应依次询问以下 6 个问题：

1. 今日主线是什么？
   - 工作要推进什么？
   - 自己的事要推进什么？
   - 下班后准备做什么？
2. 今天还记得哪些故事 / 模型？
   - 每个故事背后的道理，用一句话说出来。
3. 今天有什么新鲜事或新信息？
   - 它让你想到什么机会、风险或方向？
4. 身体底盘怎么样？
   - 睡眠、困倦、脑蒙、饮食、大便、胃口、抽烟、用药 / 调理有什么变化？
5. 今天有什么内耗或负罪感？
   - 哪件事占用了主线？
   - 它是在提醒你调整，还是只是在自我攻击？
6. 今天运动 / 恢复了吗？
   - 如果还没有，今天能做的最小恢复动作是什么？

## 用户回答后的处理流程

收到用户回答后，Skill 应执行：

1. 提炼今日主线
   - 今天真正重要的 1-3 件事。
   - 哪件事如果不做，晚上最容易焦虑。

2. 检查故事迁移
   - 用户还记得哪些故事。
   - 是否能说出故事背后的道理。
   - 是否能把道理迁移到今天的真实事件。

3. 提取新鲜事与反思
   - 记录新事件或新信息。
   - 识别其中的情绪、欲望、机会、风险、关系模式或判断模式。
   - 对时效性信息，必要时联网确认，不把传闻直接当事实。

4. 检查身体阳
   - 睡眠、饮食、精力、运动、疼痛、抽烟、暴食、熬夜等。
   - 判断身体是在支撑野心，还是被消耗。

5. 检查负罪感
   - 负罪感对应什么行为。
   - 它是在提醒调整，还是在制造无效内耗。
   - 区分“信号”和“自我攻击”。

6. 检查运动
   - 是否运动。
   - 运动对身体、情绪、自控和主线工作的影响。

7. 归结到用户 Skill
   - 将当天信息映射到阳维度。
   - 更新用户模式、短板、触发器、训练建议。
   - 对后续 Skill 设计产生影响时，写入相关设计文档。

8. 输出今日建议
   - 今日主线。
   - 身体底线。
   - 一个风险提醒。
   - 一个故事模型复习点。
   - 一个最小行动。

## 输出格式

```text
今日主线：
{1-3 件最重要的事}

我看到的模式：
{从回答中提炼出的模式}

阳维度映射：
{身体 / 情绪 / 自控 / 认知 / 判断 / 风险等}

今天的风险提醒：
{一个最值得注意的风险}

今天的最小行动：
{一个用户愿意做、做得下去的动作}

需要记录进 Skill 的内容：
{新增模式 / 修正 / 触发器 / 边界}
```

## 日志

每日回答应记录到 `DAILY_CHECKIN_LOG.md`。

记录字段：

- 日期
- 今日安排
- 记得的故事与道理
- 新鲜事与反思
- 身体状况
- 负罪感
- 运动情况
- 今日主线
- 阳维度映射
- 最小行动
- 需要沉淀进 Skill 的内容

## 边界

- 不把每日检查变成说教。
- 不一次给太多任务。
- 如果用户回答很乱，先收束成一个主线。
- 如果用户状态差，优先保身体、现金流、关系和主线工作。
- 用户理解不等于接受，接受不等于能行动。建议必须落到用户愿意做的最小动作。
